# رصد خبر — داشبورد زندهٔ تحلیل اخبار

داشبورد فارسی (RTL) برای رصد، ترجمه و تحلیل خودکار اخبار فارسی و بین‌المللی. داده‌ها از خوراک‌های RSS/Atom منابع مختلف خوانده می‌شوند، خبرهای انگلیسی به فارسی ترجمه می‌شوند و همهٔ شاخص‌ها به‌صورت درصد محاسبه و نمایش داده می‌شوند.



## اجرا

```bash
npm start          # سرور داشبورد روی پورت ۳۰۰۰ + به‌روزرسانی هر ۵ دقیقه
npm run update     # یک بار تولید داده (data.json و news.xlsx)
npm test           # تست زنجیرهٔ منابع نرخ (بدون نیاز به شبکه)
PORT=8080 npm start
```

مرورگر: `http://localhost:3000`

## دستیار مدیر (فقط روی سرور خودت)

آدرس: `http://localhost:3001/admin` — این صفحه در GitHub Pages منتشر نمی‌شود، چون آنجا نه رمز امن وجود دارد نه جای نگه‌داشتن کلید مدل.

1. در فایل `.env` (که در گیت نمی‌رود) مقدار `ADMIN_PASSWORD` را بگذار؛ بدون آن ورود ممکن نیست.
2. برای فعال‌شدن چت، `ZAI_API_KEY` (و در صورت نیاز `ZAI_API_BASE` و `ZAI_MODEL`) را اضافه کن؛ هر اندپوینت سازگار با OpenAI هم با `OPENAI_API_KEY` کار می‌کند.
3. `npm start` و بعد ورود با رمز مدیر. نشست ۱۲ ساعت اعتبار دارد، کوکی `HttpOnly` است و بیش از ۱۰ تلاش ناموفق ورود در ۵ دقیقه مسدود می‌شود.

**افزودن منبع و کانال از پنل:** در `/admin` کارت «منبع خبری و کانال تازه»: نام و آدرس فید RSS/Atom را بده و «افزودن منبع» را بزن (سرور همان‌جا فید را می‌خواند و اگر خوراک نبود یا خالی بود اضافه نمی‌کند)؛ برای تلگرام فقط `@channel` یا لینک `t.me/...` را بده (سرور پیش‌نمایش عمومی کانال را تست می‌کند). هر مورد در `.custom-sources.json` (خارج از گیت) ذخیره می‌شود و با «حذف» همان‌جا برمی‌گردد. منابع پیش‌فرض از این مسیر قابل حذف نیستند و لیست را با کد می‌شود عوض کرد.

**هشدار خودکار:** سرور هر ۱۰ دقیقه منابع خبری و مسیرهای پخش زنده را بررسی می‌کند و این سه حالت را با پیام فارسی در کارت «هشدارها»ی `/admin` ثبت می‌کند: منبعی که خطا می‌دهد، منبع سالمی که مدت‌ها خبر تازه نداده («سکوت خبری»)، و شبکه‌ای که هیچ مسیر پخشی‌اش پاسخ نمی‌دهد. تکرار خرابی حداکثر هر ۳۰ دقیقه و تکرار سکوت خبری هر ۶ ساعت است و بعد از برگشت وضعیت، پیام «برطرف شد» می‌آید. حد سکوت خبری با `ALERT_SILENT_HOURS` (پیش‌فرض ۲۴) عوض می‌شود؛ منابعی که هیچ خبر دارای تاریخ در داده ندارند هشدار نمی‌دهند تا پیام تکراری ساخته نشود. برای دریافت همین هشدارها در تلگرام، در `.env` بگذار:

```
ALERT_TELEGRAM_BOT_TOKEN=توکن-بات-از-BotFather
ALERT_TELEGRAM_CHAT_ID=شناسهٔ-چت
```

شناسهٔ چت را بعد از فرستادن یک پیام به بات، از `https://api.telegram.org/bot<TOKEN>/getUpdates` بردار. بدون این دو مقدار، هشدارها فقط در پنل دیده می‌شوند و هیچ پیامی رد نمی‌شود. دکمهٔ «تست تلگرام» در پنل اتصال را بررسی می‌کند.

سرور فایل `.env` را خودش می‌خواند. رمز نخستین بار از `ADMIN_PASSWORD` به هش scrypt تبدیل و در `.admin-auth.json` (خارج از گیت، دسترسی ۶۰۰) ذخیره می‌شود؛ بعد از آن **رمز از داخل پنل /admin → «تغییر رمز مدیر»** عوض می‌شود و همان فایل مرجع می‌ماند. با هر تغییر رمز، راز نشست هم عوض و همهٔ نشست‌های قبلی باطل می‌شوند.

ابزارهای دستیار: `site_status` (وضعیت داده‌ها)، `stream_health` (بررسی مسیرهای پخش زنده) و `refresh_site` (اجرای به‌روزرسانی کامل). کلید مدل فقط سمت سرور خوانده می‌شود و هرگز به مرورگر نمی‌رود.

**بدون کلید API هم کار می‌کند:**

- **مدل محلی رایگان:** [Ollama](https://ollama.com) را نصب کن، `ollama pull llama3.2` و بعد `npm start`؛ پنل خودش مدل محلی را پیدا می‌کند (`OLLAMA_URL`/`OLLAMA_MODEL` اختیاری). داده از کامپیوتر تو بیرون نمی‌رود.
- **حالت بدون مدل:** اگر مدلی نصب نباشد، پیام‌هایت به دستورهای آماده تبدیل می‌شوند: «وضعیت سایت»، «سلامت پخش»، «به‌روزرسانی خبرها». همین کارها از مسیر `/admin/api/tool` هم بدون هیچ مدلی اجرا می‌شوند.

## میزبانی روی GitHub Pages

گردش‌کار `.github/workflows/update.yml` تست‌ها را اجرا می‌کند، `data.json` و `news.xlsx` را بازتولید می‌کند و خروجی را روی **GitHub Pages** منتشر می‌کند (نسخهٔ تولیدشده به‌صورت artifact منتشر می‌شود و `data.json`/`news.xlsx` موجود در مخزن، آخرین اجرای محلی است). تریگرها: `schedule` هر ۱۵ دقیقه، `push` روی مسیرهای کد، و `workflow_dispatch`؛ در پایان هر اجرا، اجرای بعدی حدود ۱۳ دقیقه بعد دوباره راه می‌اندازد تا فاصلهٔ به‌روزرسانی کوتاه‌تر شود.

برای اجرای آن:

1. در تنظیمات مخزن، Actions را فعال کنید و در **Settings → Pages** گزینهٔ Source را روی **GitHub Actions** بگذارید.
2. برای زنجیرهٔ اجرای خودکار، Secret با نام `NEWS_RADAR_TOKEN` بسازید (Personal access token با مجوز **Actions: Read and write** روی همین مخزن). بدون آن، اجراهای زمان‌بندی‌شده و دستی همچنان کار می‌کنند اما اجرای بعدی خودکار شروع نمی‌شود.
3. (اختیاری) برای سهمیهٔ بالاتر ترجمه، Secret با نام `MYMEMORY_EMAIL` بسازید.
4. (اختیاری) اگر ترجمهٔ اختصاصی دارید، `LIBRETRANSLATE_URL` و در صورت نیاز `LIBRETRANSLATE_KEY` را به‌عنوان Secret اضافه کنید.

> GitHub Actions حداقل بازهٔ ۵ دقیقه دارد و ممکن است چند دقیقه تأخیر داشته باشد؛ برای به‌روزرسانی هر ۵ دقیقه از `npm start` روی یک سرور استفاده کنید (بازهٔ سرور محلی با `UPDATE_INTERVAL_MINUTES` تغییر می‌کند).
